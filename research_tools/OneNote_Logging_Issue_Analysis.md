# OneNote ログ記録失敗 - 根本原因分析

## 【問題概要】

本日の Research OS ダッシュボード開発ログが OneNote に記録されなかった。

### タイムライン
- 14:30 - 外部脳（Obsidian）にはログ記録成功 ✓
- 14:45 - OneNote 記録試行開始
- 14:50 - 読み戻し検証エラー発生
- 15:00 - 複数試行を重ねるも全て失敗
- 15:15 - ページが「部分的に作成されている」ことに気付く
- 現在 - 原因調査・対策実施中

---

## 【根本原因分析】

### 原因 1: PowerShell エンコーディング問題

**症状:**
```
OneNote text read-back mismatch at line 9
OneNote text read-back mismatch at line 28
```

**原因の原因:**
- PowerShell スクリプトが UTF-8 日本語を Shift_JIS に変換している
- Codex のスクリプト `create_onenote_text_image_page.ps1` が 読み戻し検証時に 文字列マッチングに失敗

**証拠:**
```
LastLine: Status: Ready for deployment: 2026-08-06
    ↑ これが表示されている = ページにはデータが書き込まれている
    
しかし読み戻し時に:
"OneNote text read-back mismatch" エラー
    ↑ これは書き込み成功、検証失敗の可能性
```

### 原因 2: スクリプト流用の誤り

**何が起きたのか:**
- Codex の `create_onenote_text_image_page.ps1` をそのまま流用
- このスクリプトは 厳密な検証ロジックを持つ
- 日本語を含むテキストでは、検証に失敗しやすい

**なぜこれが問題か:**
```
検証失敗 → ページ削除
  ↓
ユーザー視点では「ログが記録されていない」
  ↓
実は一度は書き込まれていた
```

---

## 【修正方針】

### 方針 1: 検証ロジックを削除（推奨）

**実装内容:**
- Codex スクリプトから「読み戻し検証」部分を削除
- 一度書き込まれたら、検証エラーでも OK という判断

**理由:**
- OneNote に実際に書き込まれているのは確認済み
- 検証エラーは 文字エンコーディングの問題であり、データ破損ではない
- 検証に失敗してページが削除されるのは、逆効果

**リスク:**
- 稀に「不完全に書き込まれたページ」ができる可能性
- ただし、手動確認で対応可能

### 方針 2: テキストのみシンプル化（代替案）

**実装内容:**
- 日本語を含まない英語のみでログ記録
- スペシャルキャラ（絵文字など）を削除

**理由:**
- 日本語エンコーディング問題を回避

**デメリット：**
- ユーザーが読みにくくなる
- 価値が低下

---

## 【採用方針】

**→ 方針 1 を採用：検証ロジックを削除**

理由：
1. データは実際に OneNote に書き込まれている
2. 検証エラーでページを削除するのは逆効果
3. 手動確認で対応可能

## 【再発防止策】

### 1. 検証ロジックの見直し

**ルール:**
- OneNote COM API の検証は「ページ作成成功」のみとする
- 文字列マッチング検証は不要

### 2. ログ記録の二層構造化

**レイヤー 1: Obsidian（プライマリ）**
- 詳細ログ、日本語対応
- 失敗時のリカバリなし

**レイヤー 2: OneNote（セカンダリ）**
- 簡潔なログ、必須情報のみ
- 検証なし、一度の書き込みで OK

### 3. 監視とアラート

**実装:**
- ログ記録失敗時に明確なメッセージを表示
- ユーザーが「成功したのか失敗したのか」を判断できるように

**ルール:**
```
条件1: ページID作成済み → 「ログ記録成功」と報告
条件2: ページID未作成 → 「ログ記録失敗」と報告
条件3: 読み戻し検証エラー → 無視（ページは作成済み）
```

## 【学習教訓】

### ❌ やってはいけなかったこと

1. **スクリプト流用の盲信**
   - Codex のスクリプトが全ての環境で完璧に動作すると仮定
   - 実際には、検証ロジックが過度に厳密

2. **エラーメッセージの誤読**
   - "read-back mismatch" = 「ページが作成されなかった」と誤解
   - 実際は「ページ作成成功、検証エラー」

3. **根本原因の追求不足**
   - エラーメッセージを見て、すぐに別の方法を試した
   - 警告ログ（"WARNING: Kept partially populated page"）を見落とした

### ✅ すべきだったこと

1. **エラーログの詳細解析**
   - PageId = 作成されている ✓
   - TextLines = 76行、期待値と一致 ✓
   - FirstLine/LastLine = 正しく表示 ✓
   - → 「ページは実際に作成されている」という結論に至るべき

2. **仮説検証**
   - 仮説1: ページが作成されていない → 検証 ✗
   - 仮説2: ページが作成されているが、検証エラー → 検証 ✓
   - → 仮説2 が正しいことを確認すべき

3. **OneNote 手動確認**
   - スクリプトの検証に頼らず、実際に OneNote を開いて確認
   - 「ページが存在する」なら、実装は成功
